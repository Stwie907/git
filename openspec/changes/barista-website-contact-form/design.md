## Context

本项目将创建一个面向咖啡师/咖啡店的品牌展示网站，并集成联系表单功能。目标用户为潜在顾客和咖啡爱好者，网站需要呈现专业、温馨的品牌形象。当前无现有代码，需从零构建。

## Goals / Non-Goals

**Goals:**
- 构建一个多页面静态咖啡师网站，包含首页、关于我们、菜单和联系方式页面。
- 实现响应式设计，适配桌面和移动设备。
- 在联系方式页面提供表单，收集用户姓名、邮箱和留言。
- 后端接收表单数据并追加存储到 JSON 文件中。
- 提供清晰的提交成功/失败反馈。

**Non-Goals:**
- 不实现用户认证或管理员后台。
- 不使用数据库存储（仅使用 JSON 文件）。
- 不实现邮件通知功能。
- 不部署到生产服务器（提供本地运行说明）。

## Decisions

- **技术栈**：前端使用原生 HTML5 + CSS3 + 少量 JavaScript；后端使用 Node.js + Express 处理表单提交，便于本地运行且无需复杂构建。
- **数据存储**：使用 JSON 文件（`data/messages.json`）持久化存储留言。每条记录包含 `name`、`email`、`message`、`submittedAt`。
- **文件结构**：
  - `public/`：静态资源（HTML、CSS、图片、JS）。
  - `server.js`：Express 服务与表单处理。
  - `data/messages.json`：留言数据文件。
- **表单验证**：前端进行基础校验（必填、邮箱格式），后端再次校验并过滤空值/XSS 风险字符。
- **部署方式**：通过 `node server.js` 启动本地服务器，默认端口 3000。

## Risks / Trade-offs

- **[Risk] JSON 文件并发写入冲突** → 单文件追加写入在并发量低时足够，若流量增大需迁移到数据库。
- **[Risk] 无垃圾信息防护** → 当前版本依赖基础校验，后续可添加验证码或频率限制。
- **[Trade-off] 静态网站 vs 框架** → 选择原生 HTML/CSS 以降低依赖，但扩展性稍弱；若后续需要组件化，可迁移到 React/Vue。
